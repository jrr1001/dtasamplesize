The methodological core of dtasamplesize is confirmed. An implementation written independently from the stated equations, in a different language, with a different special‑function library and a different search strategy, selects the same total sample size in every scenario tested and returns the same assurance probability to within floating‑point noise.

Nothing in this exercise contradicts the package. Section 8 states, explicitly and with numbers, what that agreement does not establish.

01

The estimand, and how the reference differs

The quantity under test is the smallest total N such that, in a single cohort study of size N, the posterior credible intervals for sensitivity and specificity both meet their target full width in the same study, with probability at least the target assurance:

prev ~ Beta(ap, bp)  ·  nd ~ Binom(N, prev)  ·  nnd = N − nd
Se ~ Beta(ase, bse), x ~ Binom(nd, Se)  ·  Sp ~ Beta(asp, bsp), y ~ Binom(nnd, Sp)
success ⟺ nd ≥ 1 ∧ nnd ≥ 1 ∧ w(x, nd) ≤ δse ∧ w(y, nnd) ≤ δsp

The package's documentation was read to fix three conventions — δ is the full width, alpha_ci is an equal‑tailed level, and a degenerate split counts as a failure — and nothing else. No package source code was read or copied. The reference was then written from the model above and evaluated four independent ways:

  • Closed form. Beta‑Binomial marginalisation plus the conditional‑independence factorisation Σ_k BB(k;N,a_p,b_p)·P_se(k)·P_sp(N−k). This is the route the package also declares.
  • Three‑dimensional Gauss–Jacobi quadrature of the raw generative model over (prev, Se, Sp), with the sum over k left un‑factorised. The integrand is a polynomial of degree ≤ N in each variable, so Jacobi nodes weighted to the Beta densities integrate it exactly. This route never uses the Beta‑Binomial pmf at all, so it tests the marginalisation itself.
  • Exhaustive enumeration of every (nd, x, y) triple with its mass, summed without factorisation — 1,846,401 successful triples across the enumerable confirmatory scenarios.
  • Direct Monte Carlo of the generative model, budgeted by MCSE rather than brute force.

Deliberate differences from the package

  • Different environment. Python/SciPy rather than R; betaincinv rather than qbeta — two independent implementations of the Beta quantile function.
  • Different search. The reference scans the whole candidate grid from its lower bound and takes the first N reaching the target. It assumes nothing about monotonicity, so it finds the true minimum even if the assurance curve were non‑monotone.
  • A mathematical pattern, not a second approximation. For small N the quadrature and triple enumeration are exact to machine precision, so they constitute a reference standard rather than another estimate.

Version change during the run

The installed package was rebuilt from 0.6.2 to 0.6.3 by a parallel process while the grid was executing. The entire locked grid and both published scenarios were re‑run on 0.6.3: every N and every assurance value is bit‑identical across the rebuild.

06

Monte Carlo budget

Every simulation was sized by MCSE = √(p(1−p)/B), not by brute force. Grid sweeps used B = 40,000 (MCSE ≈ 0.0020 near p = 0.80); the confirmation of individual candidate sizes used B = 160,000 (MCSE ≈ 0.0010). Precision was spent only where a decision is made. Total simulation across the whole study is under 107 replications — four orders of magnitude below a 108‑per‑point sweep, and sufficient because the decisive comparisons are exact rather than simulated.

08

Three findings worth recording

The per‑arm probability is not monotone

P_arm(m) — the probability that an arm of size m meets its width target — decreases with m over long stretches. For the published Se prior it falls from 0.068288 at m = 26 to 0.063834 at m = 27, and there are 73 such reversals for m ≤ 800 (tolerance 1e-9; the same 73 hold for m ≤ 900). The reason is structural: at small m only extreme counts produce a narrow enough posterior, and the mass on those counts thins as m grows faster than new counts qualify.

The joint assurance A(N) is nevertheless non‑decreasing across all 13 scenarios examined over N = 2…900, with zero reversals. That monotonicity is observed, not proved. It matters because "the smallest N reaching the target" coincides with "the first N a bisection finds" only if the curve is monotone. The reference sidesteps the issue by scanning exhaustively; agreement with the package on all 14 scenarios is evidence that the package's search is safe here, not a proof that it is safe everywhere.

The degeneracy convention is genuinely exercised — but only at small N

At the published sizes the probability of a degenerate split is about 4 × 10⁻⁷, so the "degenerate replication = failure" rule is untestable there. At C10 (N = 3) it is 0.427: dropping the convention would move the assurance from 0.5727 to 1.0000. The package returns exactly 0.5727272727. The small‑N confirmatory scenarios are what make this convention verifiable at all.

The anti‑noise rule costs one grid step

At C11 the exact method returns N = 24 while method = "monte_carlo" at B = 40,000 returns N = 25 — the documented conservatism of accepting only at the 95% Monte Carlo lower bound. This is expected behaviour, and an argument for the exact method being the default.

09

What this does not validate

Agreement between two implementations of the same specification cannot test the specification. The reference and the package share every modelling assumption, because the reference was built to the same declared model. Fixing nd at its expected value rather than modelling the random cohort split removes roughly 21% of the required sample — this is the single largest substantive consequence of the model, and it is asserted by both implementations together, not tested by their agreement.

Shared assumptions, stated plainly

  1. The parameterisation

    Both implementations treat delta_* as a full width and alpha_ci as an equal‑tailed level, because the reference took those conventions from the package's own documentation. If the documentation is wrong about what users intend, both are wrong together — and the half‑width row above shows that error would be enormous.

  2. The generative model itself

    Both assume Beta priors, independence of Se, Sp and prevalence a priori, a conjugate Beta posterior, and a binomial cohort split. Whether that is an adequate model of a real diagnostic accuracy study — whether, for example, Se and Sp should be correlated a priori, or the reference standard treated as imperfect — is a question this exercise does not touch.

  3. Fidelity to Wilson et al. (2022)

    The reference was built from the estimand as the package states it, not from the source paper. Confirming that the package computes what it says it computes is not the same as confirming that what it says it computes matches the cited method. That comparison remains open.

  4. Everything outside the headline

    Only N_total, joint_assurance and assurance_mcse under method = "exact" were validated. The legacy diagnostic fields — n_diseased, n_non_diseased, N_total_median, N_total_P75, N_total_P90, buderer_n_se — were not, and neither was any other function in the package. The monte_carlo path was only spot‑checked.

  5. The search ranges actually scanned

    Agreement holds on the grids searched (N up to 1600 for the confirmatory scenarios, 900 for the published ones). Behaviour at much larger N, at extreme priors, or with near‑degenerate Beta parameters such as a < 1 was not systematically explored. Where a target proved unreachable within a locked range, the pre‑registered rule recorded N as infinite rather than probing further.

  6. Correlated implementation error is still possible

    Independence of environment reduces, but does not eliminate, the chance of a common mistake. Both rely on a library Beta quantile function; both were written by reading the same documentation. A subtle error shared by SciPy's betaincinv and R's qbeta, or a misreading of the specification made twice, would survive this check.
